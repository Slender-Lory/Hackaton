# Триаж: очередь из трёх пациентов

Подключён ко второй смене как дело `triage-2` в приёмной (см. `core/data/shifts.js`). Состояние хранится в `answers['triage-2'].triage`, итог применяет `useShift.resolveTriage` одним сохранением.
Локальный экран проверки: `/triage-preview.html` при `npm run dev`.
Он использует отдельный ключ `hackat.triage-preview.v1` и не меняет игровой профиль.
В production build основного index.html экран проверки не включён.

## Контракт

`TriageActivity.vue` принимает:

- `state`: null при первом открытии либо сохранённый TriageState;
- `scenarioId`: стабильный уникальный ID эпизода; по умолчанию `vet-shift-2-triage`;
- `counters`: текущие счётчики, для отображения выручки;
- `disabled`: блокировка управления во время внешней операции. Таймер продолжает идти.

События:

- `update:state(state)`: создание дедлайна и каждое изменение распределения. Сохранить немедленно, а не только при закрытии сцены.
- `resolve(result, state)`: финальный результат и соответствующий финальный state. Обновить состояние главы, флаги, счётчики и завершённость активности ОДНОЙ операцией сохранения.
- `continue(result)`: игрок прочитал результат и хочет вернуться в смену. Здесь эффекты не применять.

Не использовать только v-model для финального состояния: `resolve` намеренно передаёт результат и state вместе, без отдельного финального `update:state`, чтобы нельзя было сохранить завершённость раньше эффектов.

В родителе хранить `appliedTriageScenarioIds` (или завершённость активности) и применять эффекты только при отсутствии `result.scenarioId`. После сохранения монтировать модуль с тем же state и ID. Завершённое сохранение показывает итог без повторного `resolve`.

`result` содержит `effects`, `patientOutcomes`, `flags`, `order`, `reputationEvents`, `outcomeId`, `scenarioId`, текст. `order` — врач, помощник, ожидающий; первые двое начинают одновременно, это не три последовательных приёма. Флаги сохранить для финала главы.

Пример обработчика см. `TriagePreview.vue`: счётчики и state сохраняются одним JSON, повторное применение защищено ID эпизода. В игре использовать существующую очередь `playerStore.saveProgress`, не отдельное хранилище демо.

Изменение `scenarioId` означает другой эпизод: перемонтировать компонент через `:key="scenarioId"`. Не монтировать, пока родитель ещё загружает сохранение: null означает именно новую игру, а не «данные ещё не пришли».

## Таймер

Ровно 60 секунд с первого открытия. В state хранится абсолютный `deadlineAt`, а не счётчик тиков. Закрытие вкладки не останавливает время; просроченное сохранение разрешается сразу после восстановления. Уже назначенные роли сохраняются. Незаполненные роли занимают те, кто громче спорит: кот, кролик, пёс. Этот порядок намеренно не является верным медицинским приоритетом: бездействие имеет последствия.

Таймаут не создаёт девятый исход: он выбирает один из восьми, добавляя `flags.timedOut`. В незавершённой попытке время не обнулять. При намеренном новом прогоне создать новый эпизод/состояние и очистить его защиту повторного применения.

## Восемь исходов

Пёс Олега — критический (сбит машиной, возможно внутреннее кровотечение), кролик Жанны — срочный (запущенный ушной клещ, обещанное видео), кот Бориса Аркадьевича — плановый (15 лет, тройная оплата за главврача).

| Врач       | Миша       | Ожидающий | Решение       | ID             |
| ---------- | ---------- | --------- | ------------- | -------------- |
| Пёс        | Кролик     | Кот       | Принять позже | dog-rabbit     |
| Пёс        | Кот        | Кролик    | Принять позже | dog-cat        |
| Кролик     | Пёс        | Кот       | Принять позже | rabbit-dog     |
| Кот        | Пёс        | Кролик    | Принять позже | cat-dog        |
| Кролик     | Кот        | Пёс       | Любое         | rabbit-cat     |
| Кот        | Кролик     | Пёс       | Любое         | cat-rabbit     |
| Пёс/кот    | Кот/пёс    | Кролик    | Не принимать  | rabbit-refused |
| Пёс/кролик | Кролик/пёс | Кот       | Не принимать  | cat-refused    |

Пёс в очереди не может уйти: ему становится хуже, нужна операция. Кролик у главврача — Жанна снимет видео. Кот у главврача — тройная оплата. Ушедший кролик — плохой отзыв, ушедший кот — потерянные деньги.

Репутация — `REPUTATION`: пёс вовремя +10 / хуже −15, видео +8, все получили помощь +15, порядок +10 / −8, плохой отзыв −10, ушёл хозяин кота −5.

Экономика: пёс −3 000 ₽ расходников (при ухудшении −12 000 ₽), кролик +3 500 ₽, кот +4 500 ₽ (у главврача +13 500 ₽). От итога зависит, хватит ли кассы на прививки для фермы.

## Приёмка

1. Все 12 допустимых назначений с двумя решениями ожидания покрываются ровно восемью исходами.
2. Перезагрузка не возвращает минуту; истёкший state завершается сразу.
3. Повторное нажатие и повторный вход не начисляют счётчики ещё раз.
4. Отказ кролику или коту не превращается в противоречивое «все получили помощь».
5. Все кнопки доступны клавиатурой, назначения обозначены текстом и aria-pressed; мобильный вид одноколоночный.
6. Основной сюжет подключает компонент во второй день; от кассы после очереди зависит выбор прививок на ферме.
