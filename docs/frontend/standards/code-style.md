# Code style (JavaScript)

Основа — стандарты `cinet-nuxt` (`code-style-core.md`, `vue3-standards.md`), адаптированные под JavaScript. Линтеры: ESLint + Prettier, их конфиги — закон; правило не отключаем без причины.

## Принципы

- **Одна ответственность** у функции, компонента, composable, модуля.
- **DRY:** повторилось больше двух раз — выносим. Один раз, но сложно — даём имя.
- **YAGNI:** не строим абстракции под будущее, которого нет.
- **Ранний выход** вместо вложенных `if/else`.
- **Без магических чисел и строк** — именованные константы.
- **Минимальный diff:** не переписываем то, что не относится к задаче.

## Имена

- Говорящие: `getPercent`, `isSubmitting`, `pendingProfession` — не `getP`, `flag`, `data2`.
- **Без сокращений:** `index`, не `i`/`idx`; `event`, не `e`/`evt`; `error`, не `err`. Исключения — общепринятые `id`, `url`, `api`.
- Булевы — `is…`, `has…`, `can…`: `isOpen`, `isLastScene`.
- Обработчики действий пользователя — `handle…`: `handleClick`, `handleLocked`. Исключения: хуки жизненного цикла, публичный API composable (`submit`, `startGame`).
- Файлы: компоненты — `PascalCase.vue`, composables — `useThing.js`, остальное — `camelCase.js`.

## Функции

```js
// ✅ именованная функция — через function
function getProfessionTitles(codes) { … }

// ✅ стрелка — только как inline-колбэк
codes.map((code) => code.toUpperCase());

// ❌ функция в const
const getProfessionTitles = (codes) => { … };
```

- `const` — для значений, `let` — только когда переприсваиваем, `var` — никогда.
- Деструктуризация, `?.`, `??` (не `||` для значений по умолчанию — он теряет `0` и `''`), шаблонные строки, `map/filter/find/some` вместо циклов.
- Аргументы не мутируем — возвращаем новые значения (`[...list, item]`, `{...object, field}`).

## Константы

| Где                                | Когда                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `core/constants/index.js`          | значение нужно в **двух и более** местах: `ROUTE_NAMES`, лимиты ника и пароля, `ERROR_CODES`, `DIFFICULTIES` |
| В начале файла, `UPPER_SNAKE_CASE` | значение нужно только в этом файле: `REACT_DURATION_MS`, `HAND_SIDE_LAYOUT`                                  |
| `core/data/`                       | контент: тексты, каталоги, сцены                                                                             |

- Объекты-константы замораживаем: `Object.freeze({…})`.
- Значения, которые обязаны совпадать с backend'ом (лимиты, коды ошибок, пути), — только в `core/constants` или `core/api`.

## Модели (JSDoc вместо TypeScript)

Модели данных описываются `@typedef` в `core/types/*.js` — это зеркало контрактов backend'а. В коде ссылаемся на них через `import(...)`:

```js
/** @typedef {import('@/core/types/profession').Profession} Profession */

/** @param {Profession} profession */
function openGame(profession) { … }

/** @type {import('vue').Ref<Profession | null>} */
const pendingProfession = ref(null);
```

- Аннотируем параметры и возвращаемые значения публичных функций, `ref` со сложным значением, `PropType` у объектных props.
- Новое поле в ответе backend'а → сначала `core/types`, потом код.

## Асинхронность и ошибки

- Только `async/await`, без цепочек `.then().catch()`.
- Всё, что ходит в сеть или может упасть, — в `try/catch`.
- **Пустой `catch {}` запрещён.** Минимум — вернуть запасное значение или `console.error(error)`; ошибку сервера превращаем в текст через `getErrorMessage`.
- Уведомления (`toastStore.show`) — только в UI-слое (компонент, composable), не в `core/utils`.
- Независимые запросы — параллельно: `await Promise.all([…])`.

## Комментарии

- **Поясняющих комментариев в коде не пишем.** Код должен читаться сам: имя функции, константы, композабла.
- Допустимы только:
  - JSDoc-аннотации типов (`@param`, `@type`, `@typedef`, `@returns`) и описания полей моделей в `core/types`;
  - строка об авторстве для кода, перенесённого из стороннего проекта, если этого требует лицензия (например, MIT у порта из Inspira UI).
- Мёртвый код не комментируем — удаляем, история есть в git.

## Форматирование

Prettier, конфиг [`.prettierrc.js`](../../../frontend/.prettierrc.js):

- 4 пробела, одинарные кавычки, `printWidth: 120`, висячие запятые;
- без пробелов в фигурных скобках: `{name, title}`;
- каждый атрибут в разметке — с новой строки, если их больше одного.

Не форматируем руками — `npm run format`.
